# Changelog

Release notes live in **[GitHub Releases](https://github.com/sd0xdev/sd0x-harness/releases)**,
generated by [`.github/workflows/release.yml`](.github/workflows/release.yml) from the commits
between tags each time `package.json` changes on `main`. That is the single source of truth for
what shipped in a version; this file is not maintained in parallel.

The sections below are kept because each is the only copy of a user-facing migration
instruction. What the automation generates is a list of commit subjects and a compare link — not
the steps a consumer has to take — so the release workflow appends a version's section from this
file, when it has one, to that version's GitHub release body
(`.github/scripts/changelog-section.js`). The file also ships in the npm package.

## 5.0.0 — rules load on demand

**Recommended models: Claude Opus 5.5 or later.**

The rules a project loads at the start of every session shrank. On a fresh `/project-setup`
install the plugin-managed resident text went from 78,378 to 49,614 characters (721 → 582 lines;
the worst ecosystem, rendered with project values), and a test now holds it at or under 50,000
characters and 600 lines. The detailed procedures moved into contracts that are read when their
situation arises. What every Anchor prohibits or authorizes is unchanged, and so are the gates:
review, `/precommit` and the doc review still run exactly when they did.

### Where each block moved (4.x → 5.0)

| 4.x location | 5.0 location | Read when |
|--------------|--------------|-----------|
| `rules/fix-all-issues.md` | `rules/auto-loop.md` § Fix Obligation (core) and `skills/codex-code-review/references/scope-contract.md` § Fix Obligation | Before deferring or excepting a blocking finding |
| `rules/framework.md` | Removed — its placeholders had no consumer | — |
| `rules/auto-loop.md`: fallback trigger and `reason=` rules, thread rotation, stall and cap diagnosis | `skills/codex-code-review/references/review-common.md` § Degradation Matrix and § Review Loop; `skills/codex-code-review/references/loop-diagnostics.md` | A fallback dispatch or rotation; diagnosing a stall |
| `rules/git-workflow.md` § Push safety and § Proactive Offer / Goal mode; `rules/discretion.md` § Efficacy Boundary | `skills/push-ci/references/authorization-contract.md` | Before any commit offer, Goal-mode commit or push |
| `rules/testing.md`: evidence model, exception gates, Adequacy Gate sentinels, execution | `skills/test-review/references/testing-contract.md` | Test or AC-evidence work |
| `rules/docs-numbering.md` split procedure and exemptions; `rules/docs-writing.md` comment-block counting and checker | `skills/doc-review/references/documentation-contract.md` | Splitting a feature doc; an exemption; changing the checker |
| Override resolution tables (`auto-loop.md` § Override Contract, `testing.md` and `git-workflow.md` § Project Customization) | `rules/override-contract.md` — path-scoped, installed beside your `*-project.md` files | Interpreting, auditing or editing an override |

Each resident rule keeps a compact core and names its contract. The template's new
§ Contract Triggers table maps eight situations to their contracts: read the contract first, and
if that Read fails, stop the governed action. The `skills/…` paths resolve under the plugin root,
which the SessionStart hook now prints as `Plugin root:`.

### Upgrading an installed project

1. Update the plugin.
2. Run `/install-rules --all`. It upgrades the managed rules you have not modified and installs
   `override-contract.md`. A `fix-all-issues.md` or `framework.md` is removed only when
   `.sd0x/install-state.json` records it and its content still matches that entry; a copy with
   no manifest entry, or one you edited, is kept and reported. `/claude-health --scope sync` lists
   any that remain as `RETIRED` — move whatever you still need into your own rules, then delete the
   file and its line in `.claude/CLAUDE.md`.
3. Copy § Contract Triggers from the plugin's `CLAUDE.template.md` into `.claude/CLAUDE.md`.
   Without it, a session that invokes no skill has no pointer to the moved contracts.
4. **No `*-project.md` edit is required.** Your overrides keep working, and the plugin never
   modifies them.

**Rules installed without the plugin.** Rules copied by `/install-rules` into a project where the
plugin is not loaded have no `skills/…` contracts to read. A trigger's Read fails there and the
governed action stops — a user-authorized push, for example, stops at the push authorization
contract. This case is not handled beyond this note.

## Historical: 3.0.0 (2026-04-05) — commands/ removed

> **Deprecated** — the 3.x line is suitable only for models before Claude Opus 4.8.

### Breaking Changes

- **Removed `commands/` from npm distribution**: The `commands/` directory
  is no longer included in the published package. Skills are now the only
  distributed and maintained entry points.
  - If you previously referenced `commands/<name>.md` in custom tooling,
    update to `skills/<name>/SKILL.md`.
  - Locally copied command files in `.claude/commands/` may still function
    but are unsupported and no longer updated.

### Migration Guide

1. **No action needed** for normal `/command-name` usage — Claude Code's
   skill-first resolution (introduced in v2.2) handles routing automatically.
2. **Custom scripts** referencing `commands/*.md` paths must update to
   `skills/*/SKILL.md`.
3. **Test files** have moved from `test/commands/` to `test/skills/`.
